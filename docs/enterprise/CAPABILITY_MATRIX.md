# 56-feature implementation and qualification matrix

Release: **0.3.0, standalone**. This matrix is deliberately not a list of 56 green checkmarks. Working local implementations, unqualified integrations, narrower capabilities, deployment templates and external organizational obligations are different things.

**Implemented** means there is a working tested path in this release, subject to the stated limit. **Partial** means some of the requested scope is working but a material part remains absent or unqualified. **Template** means executable configuration or an integration bridge is supplied, not a fully managed service/provider. **External** means the operator must obtain staff, independent assessment, legal work or contractual commitments. See `../TESTING.md` for exact evidence and environment limits.

Source basenames refer to `src/ordeal_platform`, `src/ordeal_agent` or `tests/platform` unless another path is shown.

## Release boundary

The tested deployment is a local/small-team installation with isolated customer-owned runner code. The package is not yet independently validated as a shared, multi-tenant, internet-exposed enterprise SaaS. Do not translate the breadth of these features into an uptime claim, certification, isolation guarantee, or a claim of beating a competitor without matched workload benchmarks.

## Highest-priority qualification work

Run native-browser E2E on an unrestricted host; run every claimed framework against pinned real dependencies; exercise Docker isolation and egress; run PostgreSQL concurrency/failover/migration and S3 retention tests; verify the real IdP and connector accounts; perform an external security assessment; measure capacity and restore objectives; finish payment/support/legal operations before selling contracts that depend on them.
