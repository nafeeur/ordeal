ORDEAL
Security and transparency

Clear controls. No invented assurances.

Ordeal is an open-source, standalone agent behavior platform. This page describes the supplied software, not a certification or a hosted-service guarantee.

Implemented security boundaries

Hashed scoped credentials, revocation and expiry; project-scoped authorization; OIDC sign-in and SCIM provisioning; AES-256-GCM credential and artifact encryption; pre-storage trace redaction; immutable resource versions; signed audit checkpoints; restricted, DNS-pinned outbound HTTP; request limits; and fenced worker leases.

Deployment responsibility

The operator must configure TLS, identity-provider settings, network egress, encryption-key custody, database backups, retention, and access reviews. SQLite is intended for local and small installations. Multi-replica deployments require PostgreSQL and operational validation.

Docker execution is constrained by default. Trusted-process execution is not a sandbox and is only for code owned and allowlisted by the runner operator. Provider-side agent actions are not automatically reversible.

Data handling

Trace redaction uses configurable field suppression and common pattern detectors. It cannot guarantee detection of all personal or confidential information. Apply redaction before export when raw data must not leave the application boundary. Uploaded binary artifacts are encrypted, not automatically inspected for PII.

Production trace snapshots only contain observed evidence. OTLP does not provide proof that a complete execution has been captured. Third-party model calls and optional connectors send data only when configured by an operator.

Certification and service status

No SOC 2 report, ISO 27001 certification, HIPAA assurance, PCI certification, independent penetration-test conclusion, contractual uptime SLA, or staffed support commitment is provided by this source release. Those require organization-specific controls, external assessment, and actual service operations.

Operational documents

The source archive includes the threat model, deployment guide, backup and restore procedure, incident-response template, vulnerability disclosure guidance, control-evidence checklist, tested-feature matrix, and release test report. Configure real security and support contacts before offering the product commercially.
